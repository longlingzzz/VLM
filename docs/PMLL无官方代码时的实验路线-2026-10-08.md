## 3. 代码基础确实存在，方法实现仍缺

【本次已核实】[LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory)官方说明支持 Qwen2.5-VL 和 Windows 量化 LoRA（QLoRA）相关配置。模型候选 [Qwen2.5-VL-3B-Instruct](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct)有作者模型卡，支持调节输入图片像素预算；本项目未验收该模型在用户设备上的训练显存。

库内 [FINER 2026](https://github.com/ExplainableML/finer)包含现成 LLaMA-Factory 副本及 Qwen 训练入口。本次只读检查这些文件：

- [train/README_train.md](https://github.com/ExplainableML/finer/blob/main/train/README_train.md)：训练与公开数据准备说明。
- [prepare_training_data.py](https://github.com/ExplainableML/finer/blob/main/train/prepare_training_data.py)：下载、解压、重写图片路径、登记数据集。
- [SFT trainer](https://github.com/ExplainableML/finer/blob/main/train/LlamaFactory/src/llamafactory/train/sft/trainer.py)：生成式监督微调训练器，包括损失计算入口。
- [Qwen 配置](https://github.com/ExplainableML/finer/blob/main/train/LlamaFactory/examples/train_lora/qwen2_5vl_lora_finer_tuning.yaml)：实际为 7B、DPO、LoRA rank 32 的 FINER 配置。
- [Qwen 启动脚本](https://github.com/ExplainableML/finer/blob/main/train/LlamaFactory/sbatch_train_qwen25vl_finer_tuning.sh)：默认四卡 SLURM 启动。

【关键区别】PMLL 是加权自回归监督目标；不能直接使用 FINER 的 DPO 配置当成 PMLL。可以复用加载模型、图文数据处理、LoRA、训练与检查点保存代码，再在 SFT 路径实现论文损失。通用框架提供训练基础，不提供 PMLL 的 MLR/RWR/ATO。

## 4. 推荐的执行顺序

### 第一步：验收单卡工程

【建议配置｜尚未运行】Qwen2.5-VL-3B-Instruct、4-bit QLoRA 候选、batch 1、短序列、受限图片 token、梯度检查点；先用约 100 条真实图文样本跑几十步普通 SFT，再确认保存/重载适配器和推理可用。小试跑只回答代码是否可训练、显存是否足够，不作方法效果结论。量化后是否可用需实际测量，不能用模型参数量推导运行保证。

原文教师写 32B，精确检查点未给定。概念统计可离线计算并缓存，学生微调与教师统计分开计成本；若无法使用对应教师而换小模型，应列为方法适配差异，不能默称官方配置。不得假定存在远程设备或作者统计缓存。

### 第二步：数据从 COCO2017 开始，先审计再定义长尾

【沿用此前原文核查】PMLL 采用 COCO2017 等来源，因此优先考虑 [COCO 官方数据](https://cocodataset.org/#download)以减少任务偏离。使用训练图片、实例标注与描述构造图文监督，保持描述与类别生成目标；多标签图片的类别输出和评测解析需在协议中明确，不假定已有实现。

先在训练集内建立小型开发池，统计各概念的独立原图数、文字提及频率及实际监督条目数，再判断是否存在用户要检验的文字相对丰富、独立图片稀缺。若需人为抽样，保存种子、图片 ID 和抽样规则，明确称控制构造的模态不一致长尾。不能把重复配给同一图片的文字算作新增独立图片，也不能仅凭文字条目多就认定有更多有效知识。

多标签图片含多个概念，逐类配额不一定独立可满足；按实际最终频次报告头尾，而不是只报设定目标。验证与评测按原图 ID 分离，同图不同描述不能跨划分。官方 val 用于最终评测时，调参验证集另从训练集划出；测试集不参与选择和频次统计。

COCO 没有为本项目提供完整的“支持/反证/无法确认”属性三态真值。先解决长尾选择比较；如要证明属性视觉支持机制，需另外审计标注。CUB 可作为后续机制资源，但原数据不是自然长尾，也不能直接将所有二值属性当作三态真值。

### 第三步：实现并检查完整 PMLL 适配版

按原文核查的三视角统计及 MLR/RWR/ATO 逐步接入，保留各组件开关、词元权重和区域映射日志。检查关闭组件时回到共同 SFT 目标、提示/图片 token 不被误计作回答监督、动态难度与密度更新符合定义。缺失的提示、超参数和区域边界进入显式配置及敏感性分析，不在实现中暗中补定。

若实现或关键统计没有核齐，先不运行名为“完整 PMLL”的主比较。方法来源与缺口见 [PMLL 方法核查](PMLL方法与候选方案增量-2026-10-08.md)。

### 第四步：只做必要主对照

| 组别 | 训练池 | 目标 | 判别用途 |
|---|---|---|---|
| A | 共同完整开发池 | 普通 SFT | 验证 PMLL 适配版的增量 |
| B | 同一完整开发池 | 完整 PMLL 适配目标 | 主基线 |
| C | 给定预算随机子集 | 同一 PMLL 适配目标 | 减少数据与训练成本的参照 |
| D | 同预算 DR 适配子集 | 同一 PMLL 适配目标 | 频率重平衡的额外效果 |

C/D 使用相同尾类独立图片保护规则，匹配实际训练 token/优化预算，记录图片、概念及每图监督构成。各实际训练池重新计算静态统计是接入方法流程的比较；固定原池 n/q、ATO 保持动态的版本用于后续归因，明确是受控变体。DR 若改变概念配额，首轮仅判断重平衡整体效果；定位选点价值时再补同配额随机。DR 依赖也要先修补与验收。

### 第五步：判断是否值得继续

同时报告头/中/尾概念的类别生成指标与描述质量，沿用 PMLL 的评测定义时需要其解析和配置；没有对应实现时另定义并标为本项目指标，不与论文原值直接比。记录固定 token 的效果、训练曲线和包含特征/教师统计/选择/训练的总成本，推理成本另列。

先用一个种子筛查工程与明显问题；不能据一个种子宣布选样有效或无效。正式判断至少重复三个种子，报告逐种子结果；差异小于运行波动或额外成本抵消训练节省时，收窄结论。没有经过匹配预算随机对照的提高，不作为数据选择有效的证据。
